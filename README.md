# Ember 余烬

**用 C++17 从零手写的 CHIP-8 模拟器。** 约 5500 行，不依赖任何第三方库。

CHIP-8 不是一台真实存在过的机器——它是 1970 年代的一套**虚拟机规范**，
当初给 COSMAC VIP 那类小机器用，让同一个游戏不用为每种硬件重写一遍。
它小得出奇：35 条指令、16 个 8 位寄存器、一个 64×32 的单色屏幕、一副 16 键的小键盘。
正因为小，"把一台计算机从取指到画点完整实现一遍"这件事才有做得完的可能。

> 一台从来没被造出来过的机器，在终端里被造了出来。

```c
ember play tests\run\keyecho.ch8      # 在终端里玩
```

## 三十秒上手

```bat
build.bat                    编译（带窗口）
build.bat headless           不带窗口的构建；测试跑的就是这个
build.bat release            优化版（-O2 -DNDEBUG）
build.bat nopause            编完不停留（给脚本用）

ember play   tests\run\keyecho.ch8      在终端里玩
ember screen tests\run\digit8.ch8       不开窗口，把显存 dump 成字符画
```

**按键**：`1 2 3 4` / `Q W E R` / `A S D F` / `Z X C V`——就是 CHIP-8 那副 16 键小键盘。
**退出**：`Esc`。

> 不会开终端的话：在文件管理器里双击 `build.bat` 就能编译（脚本末尾有 `pause`，
> 窗口不会一闪而过）。玩的时候双击 `play.cmd` 最省事，它默认跑 `keyecho.ch8`，
> 也可以把一个 `.ch8` 文件直接拖到它上面。

## 命令

| 命令 | 干什么 |
|---|---|
| `ember play <rom.ch8>` | 在终端里玩。用半块字符加颜色画出那块 64×32 的屏幕 |
| `ember run <rom.ch8>` | 开一个真的窗口玩。**还没做**——headless 构建下它是一个写明的报错，不是静静地什么都不干 |
| `ember screen <rom.ch8> [--cycles N]` | 不开窗口，把显存 dump 成字符画。测试用的就是它 |
| `ember trace <rom.ch8> [--steps N]` | 逐条打印指令和寄存器变化 |
| `ember dis <rom.ch8> [--offset N] [--bytes N]` | 反汇编 |
| `ember asm <prog.asm> [-o prog.ch8]` | 汇编器：把汇编写成 `.ch8` |
| `ember selftest [--font\|--quirks-table]` | 自检 / 打印字模 / 打印全部行为开关 |

### 通用参数

| 参数 | 说明 |
|---|---|
| `--ips N` | 每秒执行多少条指令（默认 700） |
| `--hz N` | 定时器频率（默认 60） |
| `--seed N` | 随机数种子，十进制或 `0x` 开头（默认 `0xC0FFEE`） |
| `--poke A=V` | 往地址 A 塞一个字节，可重复，两个都是十六进制 |
| `--quirks NAME` | 行为开关预设，默认 `modern` |
| `--no-deltas` | trace 时只印控制流，不印寄存器变化 |
| `--ansi` | screen 时用半块 + 颜色渲染（64×16，和 play 看到的一样） |

**退出码**：`0` 正常 / `1` 用户输入有错 / `2` 用法或环境有问题。

这个划分不是随手定的：`1` 表示"重试多少次都一样"（ROM 打不开、参数写错），
`2` 表示"等一会儿重试可能就好了"（用法或环境问题）。脚本靠它决定要不要重试。

## 测试

```powershell
powershell -File tests\run_tests.ps1
powershell -File tests\run_tests.ps1 -Update     重新生成黄金文件
powershell -File tests\run_tests.ps1 -Quiet      只印失败和汇总
```

69 项，分六块：黄金文件、命令行、结构检查、渲染器检查、不变量、第三方 ROM。

### 这个项目里，"通过"有两个完全不同的意思

`tests\run\*.screen` 和 `*.trace` 是**回归测试**：它们记录的是模拟器**做过**什么，
不是**应该**做什么。`-Update` 会把当前行为——**包括 bug**——固化成"期望值"。

所以全绿只说明"和上次一样"。这在重构时正是你要的（改了实现、行为不变），
但**绝不能当成"模拟器是对的"**。

真正的正确性判据只有两个，脚本里单独分开：

1. **第三方 ROM** `tests\external\*.ch8`——存在的全部意义就是"你错了就在屏幕上画个叉"
   （`3-corax+` 验全套指令，`4-flags` 验所有 `8xy_` 的标志位）。文件没下载就整组跳过，
   所以缺了它们时那 4 项显示为 `[SKIP]` 而不是 `[PASS]`。
   这些 ROM 是 GPLv3，**故意不提交**，`tests\external\README.md` 里写了下载地址。
2. **手写且永不重新生成的期望值**（`run_tests.ps1` 里的 `$Invariants`）——
   比如 `8xy4` 的进位要落在 VF 里而不是落在和里、`700/60` 拍下定时器在
   12/24/35/47/59/70/82/94 拍不漂移、`Fx33` 把 255 拆成内存里的 2/5/5。

> **一个永远绿的测试等于没有测试。**
> 所以这个项目里有一条 `tests\prove_tests_can_fail.py`：它把每个 `8xy_` 处理函数
> 各改错一处、重新编译、跑一遍harness，**记录有几个检查变红**。
> 某个处理函数改了却还全绿，那它就是测试其实没盖住的地方。

## 架构：两条硬规则

### 一、VM 核心是纯标准 C++，绝不 `include <windows.h>`

核心（CPU、显存、定时器、quirks）完全不知道窗口、声音、控制台的存在。
所以测试可以在**没有任何窗口**的情况下驱动整台机器——**这就是 69 项自动检查
能够存在的前提**：不需要图形界面。

只有两个文件能碰 `windows.h`，而且 `build.bat` 里有一条 lint 专门盯着这件事：

- `platform_win32.*`——平台层本体（窗口、声音），**整个包在 `#ifdef EMBER_GUI` 里**
- `utf8path.*`——打开 UTF-8 路径的兼容层，它有 POSIX 的 `#else` 分支，所以核心照样
  能在别的平台上编过

其余任何文件里出现 `<windows.h>` 就是**构建失败，不是代码评审意见**。

那条 lint 是一条**不做解释的字面字符串搜索**，不是正则。代价是连注释里提到它都会触发
（所以正文里谈它要写成 `windows.h` 不带尖括号）。这是明知故犯的取舍：

> 一条不需要人去判断的 lint，才是不需要人去 debug 的 lint。

### 二、指令表只有一份

`opcodes.hpp` 是整个项目**唯一一份**指令表。反汇编器（读名字）、汇编器（写名字）、
`cpu.cpp`（执行名字）、`selftest`（检查四者一致）全都从这里取。

如果允许第二份，两份迟早会对不上，而对不上的表现是"反汇编出来的东西汇编不回去"——
这种 bug 特别难定位。所以 `selftest` 会把**全部 65536 个 16 位值**走一遍
"译码 → 反汇编 → 汇编 → 译码"，任何一个不一致都会在那一步暴露。

    error.*                 两类错误（EmberError / 另一种）

  tests\
    run_tests.ps1           测试 harness
    prove_tests_can_fail.py 证明"测试能失败"
    run\                    自制的测试 ROM（.ch8）+ 黄金文件（.screen / .trace）

## 几个刻意的设计决定

**显存每个点存 1 个字节，不是 1 个 bit。** 2048 个点用位压缩只要 256 字节，
省 8 倍内存。但这点内存在今天根本不值一提，而位运算会带来两类 bug：
移位方向搞反（左边第一个像素是最高位还是最低位？），以及"改一个点却碰了邻居"。
**用 8 倍内存换掉一整类 bug，是划算的。**

**`Clock` 不知道墙钟时间。** 它只知道两条指令之间隔了多少"比例"，不知道真实世界过了多久——
真实时间是调用方量出来、当参数传进来的。这样"跑 40 条指令后的状态"才是**可复现**的，
测试才写得出来。（自己读系统时钟的话，同样的输入会给出不同的结果。）

**追踪输出是整个项目最有用的调试工具。** 理由比"好比对"更锋利：黄金文件会在
**行为开始出错的那一条指令**上分叉，而那一行的反汇编列就写着"这条指令本来该干什么"。
屏幕转储只能告诉你"上游某个地方错了"，然后你就得开始二分查找；追踪直接把那一条指给你。

**渲染层是纯标准 C++，只生成字符串。** 真正把字符串写出去的是调用方。
这样"画出来的东西对不对"本身可以被测试，而不是只能靠眼睛看——而那正是要避免的。

**quirks 不是"要不要兼容"的问题，是"必须做成开关"的问题。**
CHIP-8 是 1977 年为 COSMAC VIP 写的，后来被移植到无数平台上，每个移植者都遇到
同一批"原文档没写清楚"的地方，于是各自选了一种做法。几十年下来，同一个操作码在不同
模拟器上行为不一样，而**游戏 ROM 是按其中某一种写的**。所以同一份代码、换一组开关，
才能同时跑通不同年代的程序。

`selftest --quirks-table` 会把所有开关的当前值打出来。

## 踩过的坑

按踩到的顺序记，都是真踩出来的：

- **`.bat` 文件里绝对不能写中文。** `cmd.exe` 用系统 OEM 编码（本机是 GBK）读批处理文件，
  而文件是 UTF-8 存的。中文那 3 个字节被当 GBK 解码时会错位，**吃掉后面的换行符或 `^`**，
  行边界一塌，注释的尾巴就被当成命令执行了。所以 `build.bat` 全用 ASCII，中文文档只放在
  这个 README 里（UTF-8 在这里会被正确处理）。

- **`.ps1` 同理。** Windows PowerShell 5.1 在没有 BOM 时用 ANSI 编码读脚本。
  所以 `run_tests.ps1` 也保持纯 ASCII，它要检查的中文报错改用**退出码 + 一段 ASCII 片段**
  来断言。

- **`g++ -o ember.exe src\*.cpp` 不成立。** cmd 不展开通配符（那是 Unix shell 的习惯），
  MinGW 的 g++ 也不展开，它会原样收到字符串 `"src\*.cpp"` 然后报 "Invalid argument"。
  得用 cmd 自己的 `for` 循环把文件列表拼出来，而且要用 `setlocal enabledelayedexpansion`
  配合 `!SRCS!`（用 `%SRCS%` 的话整个 for 体在开始前就展开完了，那时 `SRCS` 还是空的）。

- **`-lwinmm` 必须放在源文件列表之后。** GNU ld 从左到右解析，一个写在需要它的目标文件
  **之前**的库会被静默丢掉，于是每个 `PlaySound` 调用都变成未解析符号。

- **TDM-GCC 默认就静态链接 libstdc++**（这是 TDM 相对原版 MinGW-w64 的改动），
  所以 `-static-libstdc++` / `-static-libgcc` 是多余的。

- **`findstr /r` 的正则不能用来做这条 lint。** 试过，它内置的正则引擎用这里的模式
  匹配上了**每一个**文件（用一个探针脚本验证过）——一条永远不可能通过的 lint 比没有 lint 更糟。
  **`^` 也不能用**：for 循环体里的 caret 是 cmd 的转义字符，在 findstr 看到它之前就被吃掉了。
  所以最后是一条纯字面匹配，不做任何解析。

## 还能做什么

由易到难：

1. **蜂鸣器**——`platform_win32` 里已经有 `PlaySound` 的接线，等阶段 7。
2. **`run`：真正的 Win32 窗口**——阶段 7 的主体。要开窗口、把 64×32 放大贴上去、
   处理窗口消息循环。
3. **super-CHIP / XO-CHIP 扩展**——更高的分辨率、更多指令。
   `quirks.hpp` 那套开关已经为"同一操作码多种行为"铺好了路。
4. **把 `tests\external\` 那几个 ROM 下下来**——`3-corax+` 和 `4-flags` 是唯一两个
   不依赖"和上次一样"的正确性判据，装上之后测试的说服力会完全不同。
